# Lestoroer Godot Fork

Глобальные правила — `~/agent-config/shared/AGENTS.md`.

## Работа с форком

Перед изменением движка или изучением отличий от Godot прочитай [fork.md](fork.md).
Найди нужную фичу, прочитай её карту и найди соответствующие маркеры в коде.
Реализацию смотри в коде.

## Документы

- `fork.md` — список фич форка со ссылками на их карты и на `fork/fixes.md`.
- `fork/<фича>.md` — короткий список крупных частей фичи и затронутых файлов.
  Например: «Отражения — ссылки на файлы реализации».
- `fork/fixes.md` — самостоятельные исправления движка, которые не относятся
  к конкретной фиче: суть исправления и затронутые файлы. Исправление внутри
  существующей фичи остаётся в её карте.
- В карты не добавляй подробности алгоритмов, историю работы, замеры и планы.
  Документация наших изменений ограничена `AGENTS.md`, `fork.md` и картами
  в `fork/`. Дополнительные README и другие описания не создавай.

## Маркеры и комментарии

- Каждый изменённый участок отмечай комментарием `lestoroer#<фича>`.
  Имя фичи совпадает с именем карты: `fork/gi.md` → `lestoroer#gi`.
  Для самостоятельных исправлений из `fork/fixes.md` используй `lestoroer#fix`.
- У файла, целиком добавленного для одной фичи, достаточно маркера в начале.
- В одном файле могут быть изменения разных фич: отмечай их участки отдельно.
  У общего участка укажи маркеры всех относящихся к нему фич.
- По умолчанию пиши код без поясняющих комментариев. Комментарий нужен только
  там, где из кода неясна причина решения, важное ограничение или неожиданное
  поведение. Кратко объясни именно это — остальное должно быть понятно из кода.
  Маркеры обязательны независимо от поясняющих комментариев.

При изменении кода сохраняй маркировку. Карту обновляй, если изменился состав
её частей, их назначение или расположение файлов. Для новой фичи добавь карту
и ссылку в `fork.md`. Для поиска GI: `git grep -n -F 'lestoroer#gi'`.

При обновлении Godot проверяй сохранность изменений по картам, маркерам
и diff с upstream. Одного количества маркеров для проверки недостаточно.

## Ветки

- `<minor>-base` — исходник upstream; напрямую в него не коммитят.
- `lestoroer/main` — общие изменения и движок Voxel Underworld.
- `interior-star/main` — общие изменения плюс Surface Cache GI для Interior Star.
  Игра собирается из этой ветки; коммит закреплён в её `tools/engine/engine.json`.
- В интеграционные ветки изменения попадают через `git merge --no-ff`.
  Для общих изменений создавай `lestoroer/feat-*` или `lestoroer/fix-*`,
  для Interior Star — `interior-star/feat-*` или `interior-star/fix-*`.
  Коммиты помечай `[Lestoroer]`.
- `lestoroer/main` вливается в `interior-star/main`; обратного слияния нет.
  Общий код проверяют в обеих играх, включая Quest для Voxel Underworld.
- Не делай rebase или force-push интеграционных веток. Сборки в Git не добавляй.

## Обновление upstream и сборка

1. Выбери точный коммит релиза upstream и сохрани текущие вершины веток тегами.
2. Обнови `<minor>-base`, влей её в `lestoroer/main`, затем — в `interior-star/main`.
   Конфликты проверяй по карте и коду. Сравнение с upstream должно содержать
   отличия форка; одного количества маркеров для проверки недостаточно.
3. При смене версии очисти объектники своей сборки, затем пересобери движок.
   Повседневная сборка — без `dev_build=yes`; проверь версию готового бинарника.
4. Сборка и закрепление движка Interior Star — по [инструкции игры](../is-game/docs/run/README.md).
   После изменений рендера используй проверки [освещения](../is-game/game/features/lighting/README.md#проверки).
   Для Quest пересобери также Android templates с модулями проекта Voxel Underworld.
